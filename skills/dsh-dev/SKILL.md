# 呼叫蓝色大肥鱼 · dsh-dev

Codex 负责理解需求、选择能力、调度和独立验收；dsh 默认负责实现。以当前可观测状态为准，不把旧文档、已安装包或 Agent 自述当作运行证据。

## 运行前提

- 本 skill 面向具备内置浏览器交互能力的 Codex 桌面应用。进入网页流程前按 [兼容性检查](references/compatibility.md) 核对终端执行、右侧浏览器展示、真实网页交互和必要项目读取能力；缺项时说明缺项与下一步，不虚构工具。仅管理本机默认项目不需要连接 dsh。仅有技能加载能力不代表能运行完整流程。
- 使用本 skill 前，请先自行运行并使用至少一次 DeepSeek Harness（dsh），完成 API key 配置，并确认能够正常发送请求、获得模型回复。检查当前模型/提供方的非敏感状态；未配置、认证失败或无法确认时请用户回到 dsh 完成配置，不要求把 key 粘贴到 Codex、仓库或反馈中。只打开不发模型测试；开发以必要任务验证连接。
- 本 skill 使用已配置好的 dsh，不申请 key、不充值、不提取其他应用凭据；模型调用、压缩、重试和多 Agent 的费用由用户承担。

## 先确定意图

- **只打开**：发现、启动或复用服务，在 Codex 右侧打开，确认网页就绪并检查下述会话默认值后结束。尚未完成首次模型配置时也可展示页面并指出缺项，由用户自行配置；不报告模型可用，不进入开发。可以核对当前 workspace；不要发送测试消息、创建开发任务或安装开发插件。
- **委托开发**：读项目约束，确定验收项，选择能力，提交、跟进、验收，失败则定点修正。
- **继续已有任务**：先按项目、目标和会话标识恢复；核对最新消息、运行状态、文件和 diff，再决定等待、验收或补充指令。找不到唯一对应会话且不能自行消歧时再问用户。
- **管理默认项目**：只按用户明确要求保存、修改或清除独立本机配置；不因此打开 dsh 或提交任务。
- 没有明确 dsh 操作意图时不启动、不打开、不提交。`$dsh-dev` 配合开发目标表示委托；单独提及或询问其功能不表示执行授权。

## 先确定项目

按 [项目选择与本机配置](references/projects.md) 使用 `scripts/project_config.py`，不要把 Codex cwd、dsh 启动目录或网页上次 workspace 当作默认值。

- 新任务优先使用用户当前明确指定的项目；指定文件时保留文件为任务对象，先确认所属项目根，歧义则询问，不直接用文件父目录。
- 新任务未指定目录时读取本机默认项目；无默认值先问并等待答复，之后才提交。每次使用前检查目录存在、可访问，指定或默认目录不可用时说明并询问，不静默回退。
- 继续任务沿用原会话已确认的项目，不用默认值覆盖；新指定目录与会话冲突时先澄清。
- 仅用户明确“设为默认 / 修改默认项目 / 清除默认项目”才保存、更新或删除配置。临时选择不覆盖默认值，配置不随 skill 发布。
- 只打开不因缺少默认项目而阻塞，也不为补齐目录擅自创建任务；需要选择项目或提交时再处理。开发提交前必须核对网页实际 workspace 与目标一致。

## 会话默认值

- **预期权限：完全访问权限。** 安装 skill 不等于授权。首次需要启用时明确告知：dsh 可能读写本机文件、运行终端命令并访问网络，实际范围受 dsh 配置、运行账户和操作系统限制；这不是严格的项目目录沙箱。核对用户对当前任务的有效授权，没有则取得授权后再切换；已有覆盖该范围的授权不重复询问。打开或恢复目标会话后检查当前值，按授权通过受支持控件设置并确认生效。**每次新建会话后再次检查**；不顺带修改全局默认权限。只打开且权限待授权时可以完成打开，开发提交须先解决。
- **推理等级：High。** 用户未指定时设置 High；用户对当前任务明确指定其他等级时，采用该等级，并在同一任务的新会话、恢复和返工中保持，直到用户更改。新建会话、切换模型后重新核验。只调整推理等级，不因此擅换模型/提供方。
- 用户后续更具体的约束优先。设置操作仍遵守执行工具的当次确认规则；未支持、未确认或未生效不能报告为成功。具体操作与能力缺口见 [会话设置检查](references/connection.md#会话权限与推理等级)。

## 执行流程

1. **保护现场。** 按上述规则确定开发任务的项目，再确认适用项目指令、分支、HEAD、已有修改和未跟踪文件。无 Git 时用文件清单/必要校验和作基线；不要初始化用户仓库或清空改动。明确允许改动范围、验收项及用户预算。只打开且未选择项目时跳过项目基线，不阻塞打开。
2. **连接网页。** 读 [连接与浏览器操作](references/connection.md)。先读当前终端输出，再按需检查进程、监听和内置标签页；对候选验证实际 dsh 页面、认证和交互。可用服务优先复用，无可用服务才启动。只打开模式完成会话默认值检查后结束，不发送任务。
3. **核对执行上下文。** 网页选定的 workspace 必须与目标路径一致；服务 cwd 不构成证明。继续任务还要确认会话身份；每次新建会话后及提交前，核验 preset、模型/提供方、完全访问权限和目标推理等级。缺少凭据时保留进度，不伪造可用状态。
4. **选择能力。** 读 [插件、调研和执行方式](references/capabilities.md)。先判断现有能力是否够用；有具体收益才查插件或安排有边界的 GitHub 调研。按复杂度、依赖、角色沟通和成本选择单 Agent、子 Agent、workflow、Agent Teams，并独立决定是否增加审评。组合能力须检查当前版本兼容性。
5. **提交一次。** 用 [任务与验收](references/task-loop.md) 整理目标、范围、验收、能力选择和预算。一般任务自行形成提示词，不逐次请求批准。发送后确认消息已进入正确会话；状态不明先查历史/运行状态，不重复提交。
6. **跟进并验收。** dsh 完成后读取实际文件和 diff，运行适度的测试、构建或界面检查；审评一致不代替证据。失败时反馈位置、复现、预期/实际和必要日志，在同一会话修正、复验。达到验收项及时结束。
7. **恢复或阻塞。** 读 [故障与恢复](references/recovery.md)。先凭实际错误区分上下文上限、输出截断、限流和账户额度，不把“token 用完”一概重试。页面断线不等于任务停了；先查内部重试和后台写入。上下文无法恢复时用精简交接在原项目继续；预算耗尽、额度不足或无新证据的重复错误则保存进度并报告阻塞。恢复后继续原验收标准，恢复成功不代表完成。

## 不可省略的边界

- 终端执行、Codex 右侧展示、网页交互是三类操作，使用当前实际提供的工具及其文档。不要虚构 CLI、RPC、插件、选择器或持久后台能力。
- 原始启动 URL、认证 token、API key、Cookie 和完整配置/日志不进入仓库、恢复记录或交付报告。认证数据仅传给其对应本地服务。
- dsh 写代码期间 Codex 默认只读验收。需直接编辑同一批文件，先确认 dsh 及其子 Agent 停止写入、明确交接，再编辑；完成后再交回。多 Agent 明确文件职责，冲突风险高时采用独立 worktree；Teams 不自动提供文件隔离。
- 用户既有授权在范围内继续有效。按上述明确配置设置 dsh 会话权限；插件安装及其他配置变更仍按来源和实际影响判断，不批量升级、不额外扩大权限、不关闭其他保护、不执行陌生安装脚本。完全访问权限不扩大任务修改范围；工具审批不能通过另一条执行路径绕过。
- 区分**静态核对、模拟验证、真实端到端实测**，以及插件的**候选、已安装、运行可用、任务实测**。最终只报告有证据支持的状态。
