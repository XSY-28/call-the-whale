# 插件、GitHub 调研和执行方式

## 插件：先查缺口，再查来源

普通文件修复/测试通常已有足够能力，跳过外部插件搜索。陌生集成、专用工具或团队协作有明确收益时：

1. 查本机包、目标 profile manifest/相关补丁及网页插件面板。Codex 的插件清单不等于 dsh 插件。
2. 对照本机版本的 README、依赖和启用方式，以及官方仓库；再看可信作者仓库、官方社区入口或 `dsh-plugin` topic。搜索摘要只作线索。
3. 对少量候选记录：解决什么缺口、版本/peer dependencies、维护与相关问题、许可证、依赖/安装脚本、读写/网络/凭据权限、实际使用方法。stars 不代表可靠性。

只读辅助清单（Python 3 标准库，无新增依赖）：

```sh
python3 /absolute/dsh-dev/scripts/inspect_dsh.py \
  --node-modules /actual/install/node_modules \
  --profile /actual/DSH_HOME/profiles/web
```

路径从当前进程/安装获得，不复制旧缓存路径。只扫描已核实的 metadata 目录；脚本支持 npm 包目录符号链接，但拒绝最终文件名不是 package.json 的重定向。它不执行包代码、不求值 YAML、不打开凭据配置；这不是针对恶意文件系统的完整安全边界。退出码 0 仅表示扫描完成，缺包仍在 JSON 中标为 manifest_missing；退出码 2 表示输入/解析等检查不完整。必须逐项检查输出，结果不证明已加载。

| 状态 | 最低证据 |
|---|---|
| 找到候选 | 当前维护者资料与匹配任务的用法 |
| 已安装 | 实际解析到的包版本及依赖 |
| 运行可用 | 目标 profile/preset 加载成功、工具/入口存在、依赖就绪 |
| 任务实测 | 当前调用成功并产生可独立核验的结果 |

未知保持未知。局部路径未找到不等于全机未安装。

## 最小安装和回退

只在收益明确且现有能力不够时安装。已有用户授权覆盖的可信来源、范围内操作不重复问；超出授权的依赖执行、费用、配置覆盖或权限扩大才请求具体确认。

核对当前 CLI 后，命令可能形如 `npx @deepseek-ai/dsh plugin --profile web add <verified-package-spec>`；目标 profile 必须来自实际服务，不能默认都是 web。先确认当前版本支持该命令及其实际使用的包管理器，不假定 pnpm 已安装。安装普通包不必然启用 bundle，更不必然进入当前 preset。

变更前私下备份受影响的 manifest、lockfile、patch，记录新增文件和目标版本。选择兼容版本，不批量升级、不全局放开安装脚本。失败时只回退自己造成的差量，先检查是否有并发配置修改。

成功后验证 bundle membership、加载错误、preset 和相关工具；有必要再做低成本调用。需要重启则先处理运行任务；热加载/新会话边界以本机版本为准。找不到合适插件就用现有能力，不把搜索变成阻塞。

## GitHub 调研

成熟功能复用、陌生 API、复杂架构和高迁移成本值得先调研；局部 bug 或明确小改动通常跳过。给一句判断理由。

需要时在 dsh 提示词加入有边界阶段：可先比较 2–3 个候选、约 10 分钟，随任务/用户预算调整。要求真实链接、解决的问题、兼容性、维护、许可证，以及采用/参考/放弃的理由。区分读过文档、查过具体代码、实际运行；没有证据就说明。

Codex 可提供官方线索，并核查影响架构、API、安全和许可证的结论。找到足够依据就实现。分别说明：借鉴思路、引入依赖、复制代码；后两者核查版本和许可证，复制保留所需版权/NOTICE/署名，无许可证不推定可复制。不运行未知安装脚本，不因调研擅换架构/技术栈。

## 执行方式

方式可组合，但须核对具体实现兼容性；独立审评是可叠加阶段。

| 方式 | 适用情形 | 需要核实 |
|---|---|---|
| 单 Agent | 修改集中、步骤依赖强、预算小；默认选择 | 项目工具、模型和权限 |
| 普通子 Agent | 1–2 个边界清晰、能独立交付的分工 | provider/tool/preset 可用；共享目录分文件 |
| workflow | 多阶段、大量独立分支、结构化汇总有益 | workflow tool、engine/provider；一两次委托通常不需要 |
| Agent Teams | 多角色需持续双向沟通、共享任务状态 | 当前 Teams bundle、团队工具和成员/UI 证据；多个子 Agent 不等于 Teams |
| 独立多 Agent 审评 | 高风险接口、跨模块修改、不同错误假设 | 限定人数/审查面、默认只读，要求位置/复现/严重度，Codex 判断 |

官方 workflow 指引要求明确请求 workflow/大规模编排；用户通过本 skill 授权 Codex 选择时，把选择及理由明确写入 dsh 任务。不要仅写“必要时并行”就宣称已经启用。

已核对的官方 Teams 文档说明可与 workflow 共存，但会禁用/替换部分普通 subagent 和同名控制工具；共享 checkout，不自动加锁/worktree。用户安装版本可能没有该 bundle，不能直接照搬最新步骤。

团队提示词写清 lead、角色的目标/输入/文件职责、依赖顺序、最大并发、汇总接口和冲突处理。有依赖的工作顺序执行，复杂度不等于并行度。能力不可用时降级单 Agent 顺序执行或已核实的普通子 Agent，说明实际方式和局限，不伪造工具调用。
