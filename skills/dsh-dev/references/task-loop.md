# 提交、跟进与验收

## 轻量消息

适用于用户明确要求发送原文或让 dsh 回答与项目无关的一般问题。未指定会话时，优先可明确识别、空闲的普通聊天；不可把问候追加到仍在开发的会话。必要时通过当前 UI 新建会话，检查模型/提供方、实际权限和推理等级（用户指定优先，否则 High）。纯聊天不自动扩大权限；检查不等于切换，也不宣称聊天是安全沙箱。指定继续某会话时核对身份和后台写入，仍在运行则等待或使用已支持的交互方式，不干扰执行。

非项目消息不调用默认项目解析，也不保存网页 workspace。确需无项目启动时沿用 [私有临时启动](connection.md#无可用服务时)；必要时经受支持 UI 选中临时目录作为隔离聊天的技术上下文，不作为开发项目或默认值。涉及本机文件、项目代码审查或修改则回到项目选择、访问、基线、权限和独立验收流程，不能靠消息分支绕过。

指定原文准确发送，不附开发契约、插件、调研或测试要求；一般问题只整理必要问题。发送前核对目标会话及正文，发送一次后确认正确历史中出现该消息和接受状态。确认丢失或状态未知先查同会话，只有确证未接收才重发，不另起副本。生成中继续观察；截断或错误按恢复分类处理，不将片段交付为最终回复。获取完整回复并确认不再生成后，以实际接收及回复作为消息验收；只打开永不走发送步骤。

## 任务契约

读取项目说明/指令、依赖与脚本、相关实现和测试；能从项目确认的细节自主处理，只问会改变结果的关键歧义。按需整理下列内容，小任务合成一段即可：

```text
任务标识：本次稳定、无敏感信息的唯一标识。
目标与预期行为：……
开发模式：普通 / MVP / 敏捷 / 组合；按需读 development-modes.md，本轮核心和延后项。
项目：已核实绝对路径及来源（本次指定 / 默认 / 原会话）、分支/基线、相关实现与项目指令；文件任务保留具体文件及确认的所属项目。
范围：允许改动的文件/行为、必须保留的原有工作。
维护：实际变化点、集中的规则/配置及职责边界；合理变化探针或检查，避免过度设计。
验收：具体输入输出、错误边界、兼容性；多项要求用稳定 A1、A2…编号，注明关键项。
能力：现有能力/已验证插件；GitHub 调研安排或跳过理由。
方式：单 Agent/子 Agent/workflow/Teams；角色、文件职责、汇总规则。
里程碑（长任务才需要）：少量 M1、M2…，各列产物/行为、允许范围、检查方法、完成依据及依赖；依赖串行，不伪装并行。
会话设置：已核验的权限与推理等级；用户对等级的明确指定优先于 High。
验证：测试/构建/运行/界面检查；不得削弱要求来通过测试。
预算：时间、并发、返工或用户费用上限；缺证据不编造费用。
交付：实际改动、命令及结果、必要来源、未完成/未验证事项。
完成后停止写入，等待 Codex 验收；敏捷每轮先完成 dsh 自审/修复，再交 Codex 核验及用户审查。越界或缺凭据时保存进度并报告。
```

模式与审查细节见 [开发模式](development-modes.md)。

不发送密钥、完整私有日志或不相关上下文；不逐次要求用户批准常规提示词。

## 提交和去重

按 [项目规则](projects.md) 解决缺少目录、无效目录、文件归属和会话目录冲突，再核对网页实际 workspace。询问后的目录答复不自动保存为默认值；目录尚未确认时不发送开发或修正消息。

发送前再确认 workspace/session、正文、任务状态，以及按任务适用的权限与目标推理等级已在当前会话生效。每次新建会话后重查，不沿用上个会话的检查结论；任务提示词中的设置描述不能代替 UI 实际状态。复杂/可恢复任务用稳定标识，可附 prompt digest；摘要不能替代消息历史。

阶段：准备 → 提交状态未知 → 已接受/运行 → 等待交互或待验收 → 修正 → 完成/阻塞。发送一次后确认正确会话出现用户消息/任务标识和执行状态。超时或断线先重连同一会话查历史、执行记录与文件；已收到只恢复/等待，已完成就验收，只有确认未接收才重发。无法确定就保留“提交状态未知”，不创建新会话碰运气。

敏捷轮次在运行后区分“待 dsh 自审/修复 → 待 Codex 核验 → 等待用户审查”；最后一项是明确等待状态，技术通过或恢复成功不能跳过。

恢复时按项目路径、session id、目标和最近消息核对；标题可能自动变化。空白会话/已归档/缺历史入口时不谎称已恢复。

token 相关异常走 [恢复分类与交接](recovery.md#token-相关异常)，不重发整个任务来掩盖失败。上下文耗尽而必须换会话时，先按恢复规则交接并确认旧会话及子任务已停止写入；新会话沿用原项目、约束、验收和推理等级，重新核验实际权限（开发默认完全访问，用户明确任务配置优先）。记录后继会话标识，提交状态不明仍先查历史，不能再创建第三个会话。恢复可执行后回到本文件的跟进与独立验收，不降低完成标准。

## 跟进

按任务时长观察有效阶段输出和等待请求，不密集刷新。可从项目确认的问题自行回答给 dsh；新权限、密钥、范围/关键决定按既有授权处理。工具失败、模型拒绝、依赖/超时都看具体证据。

用户更新需求时在同一任务更新验收项，保持原编号；增补新编号，明确替代或撤销项，提交、定点修正、交接恢复均沿用，按当前 UI 的队列/steer/停止方式处理。没有受支持且获授权的持续执行机制时，不承诺结束当前 Codex 任务后仍会自动跟进。

长任务维护简短进度摘要：最近已确认的实质进展及依据、当前里程碑、下一步、提交状态、各文件写入责任、剩余预算。完成检查、新文件、已接受消息或可核实执行阶段可算进展；重复状态和同错不算。没有新回复先核对后台 jobs、内部重试及等待交互，不仅凭静默判定卡死或重启。只有已确认阶段转换或实质进展才更新；短任务保留对话摘要，需跨轮次时复用 [私有记录](recovery.md#交接与轻量记录)。换会话继承原预算，不编造费用或将未知计数置零。里程碑不是逐项审批关卡，不强制新会话或 worktree；用户选择敏捷逐轮审查时，技术核验后进入“等待用户审查”，收到本轮反馈后才提交下一轮。

## 独立验收

1. 确认 dsh 和写文件的子任务已结束；检查实际文件、diff、未跟踪新文件与基线变化。Git diff 不含未跟踪文件。
2. 每项按稳定编号记录 **通过 / 失败 / 未验证** 与必要证据（文件/位置、复现步骤、命令结果或 UI 观察），明确 dsh 提供的线索与 Codex 本次独立核验。自述成功或多 Agent 一致无实际证据不能判通过。按验收项独立运行检查：逻辑修复覆盖触发输入/边界，构建任务跑构建，界面任务实际交互。不要只重跑 dsh 为自己写的测试。
3. 默认核对可变配置/规则是否集中、职责边界和必要变化探针，MVP 以核心全流程为完成条件。单独核对范围偏离、重要假设、用户原有修改和未跟踪文件的保留、错误路径和报告真实性。披露未查看的 diff/文件、遗漏的未跟踪文件、跳过的平台和未执行的 UI 检查；局部通过不能覆盖这些缺口。静态核对/smoke test 不等于完整回归或端到端。
4. 审评意见须有证据，Codex 判断是否符合需求；争议用复现解决，不投票、不自动采纳风格偏好。
5. 失败优先在原会话反馈失败验收编号、文件/位置、复现命令或步骤、预期/实际、最小日志和要保留的已通过行为；原会话已不可用时使用经过恢复交接的后继会话。要求定点修复后重跑受影响检查及必要回归。
6. 敏捷每轮保留 dsh 自审证据，独立技术核验后将成果交用户审查并等待；技术通过不等于本轮获用户确认，最终一轮确认后才完成。关键项失败或未验证不宣布整体完成；客观无法核验则说明具体缺口、已尝试方法和下一步，停止无意义返工。普通开发通过验收及时结束；敏捷按本轮反馈推进，最终一轮确认后结束，不引入未经请求的持续打磨或架构变更。

Codex 需直接修改时，先确认 dsh 及其后台子任务停止写入，记录当前摘要和交接范围，再编辑，完成后再交回。主 Agent 完成不证明后台已停止。

小任务几句话即可，不强制表格、JSON 或新文件。

最终交付：逐项结果与覆盖边界、文件位置、独立验证、实际模式/插件、剩余限制；不把“选择了某模式”写成“已经运行”。
