# 提交、跟进与验收

## 任务契约

读取项目说明/指令、依赖与脚本、相关实现和测试；能从项目确认的细节自主处理，只问会改变结果的关键歧义。按需整理下列内容，小任务合成一段即可：

```text
任务标识：本次稳定、无敏感信息的唯一标识。
目标与预期行为：……
项目：已核实绝对路径及来源（本次指定 / 默认 / 原会话）、分支/基线、相关实现与项目指令；文件任务保留具体文件及确认的所属项目。
范围：允许改动的文件/行为、必须保留的原有工作。
验收：具体输入输出、错误边界、兼容性。
能力：现有能力/已验证插件；GitHub 调研安排或跳过理由。
方式：单 Agent/子 Agent/workflow/Teams；角色、文件职责、汇总规则。
会话设置：已核验的权限与推理等级；用户对等级的明确指定优先于 High。
验证：测试/构建/运行/界面检查；不得削弱要求来通过测试。
预算：时间、并发、返工或用户费用上限；缺证据不编造费用。
交付：实际改动、命令及结果、必要来源、未完成/未验证事项。
完成后停止写入，等待 Codex 验收；越界或缺凭据时保存进度并报告。
```

不发送密钥、完整私有日志或不相关上下文；不逐次要求用户批准常规提示词。

## 提交和去重

按 [项目规则](projects.md) 解决缺少目录、无效目录、文件归属和会话目录冲突，再核对网页实际 workspace。询问后的目录答复不自动保存为默认值；目录尚未确认时不发送开发或修正消息。

发送前再确认 workspace/session、正文、任务状态，以及完全访问权限与目标推理等级已在当前会话生效。每次新建会话后重查，不沿用上个会话的检查结论；任务提示词中的设置描述不能代替 UI 实际状态。复杂/可恢复任务用稳定标识，可附 prompt digest；摘要不能替代消息历史。

阶段：准备 → 提交状态未知 → 已接受/运行 → 等待交互或待验收 → 修正 → 完成/阻塞。发送一次后确认正确会话出现用户消息/任务标识和执行状态。超时或断线先重连同一会话查历史、执行记录与文件；已收到只恢复/等待，已完成就验收，只有确认未接收才重发。无法确定就保留“提交状态未知”，不创建新会话碰运气。

恢复时按项目路径、session id、目标和最近消息核对；标题可能自动变化。空白会话/已归档/缺历史入口时不谎称已恢复。

token 相关异常走 [恢复分类与交接](recovery.md#token-相关异常)，不重发整个任务来掩盖失败。上下文耗尽而必须换会话时，先按恢复规则交接并确认旧会话及子任务已停止写入；新会话沿用原项目、约束、验收和推理等级，重新核验完全权限。记录后继会话标识，提交状态不明仍先查历史，不能再创建第三个会话。恢复可执行后回到本文件的跟进与独立验收，不降低完成标准。

## 跟进

按任务时长观察有效阶段输出和等待请求，不密集刷新。可从项目确认的问题自行回答给 dsh；新权限、密钥、范围/关键决定按既有授权处理。工具失败、模型拒绝、依赖/超时都看具体证据。

用户更新需求时在同一任务更新验收项，按当前 UI 的队列/steer/停止方式处理。没有受支持且获授权的持续执行机制时，不承诺结束当前 Codex 任务后仍会自动跟进。

## 独立验收

1. 确认 dsh 和写文件的子任务已结束；检查实际文件、diff、未跟踪新文件与基线变化。Git diff 不含未跟踪文件。
2. 按验收项独立运行检查：逻辑修复覆盖触发输入/边界，构建任务跑构建，界面任务实际交互。不要只重跑 dsh 为自己写的测试。
3. 核对用户原有工作、修改范围、错误路径和报告真实性。静态核对/smoke test 不等于完整回归或端到端。
4. 审评意见须有证据，Codex 判断是否符合需求；争议用复现解决，不投票、不自动采纳风格偏好。
5. 失败优先在原会话反馈文件/位置、复现命令或步骤、预期/实际、最小日志和要保留的已通过行为；原会话已不可用时使用经过恢复交接的后继会话。要求定点修复后重跑受影响检查及必要回归。
6. 通过验收及时结束，不引入未经请求的持续打磨或架构变更。

Codex 需直接修改时，先确认 dsh 及其后台子任务停止写入，记录当前摘要和交接范围，再编辑，完成后再交回。主 Agent 完成不证明后台已停止。

最终交付：结果、文件位置、独立验证、实际模式/插件、剩余限制；不把“选择了某模式”写成“已经运行”。
