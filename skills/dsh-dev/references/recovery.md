# 排错与恢复

## 分层取证

| 现象 | 证据与最小处理 |
|---|---|
| 浏览器/标签连接错误 | 查原 tab、浏览器清单与服务；重取同一标签句柄，不立刻重启 dsh |
| 401/认证失效 | 核对是否换过进程，用当前真实启动 URL 认证；缺失则保留阻塞，不关认证 |
| 服务无响应/启动失败 | 查终端增量、PID/监听、匹配版本诊断；修正已证实原因，不杀无关进程 |
| 模型接口错误或“token 用完” | 按下方分类检查当前请求的结构化错误、状态及必要脱敏日志；401/403 认证、网络超时不等于额度耗尽 |
| 插件加载/工具缺失 | 查版本、profile/bundle/preset、加载错误；核对依赖，回退自己的变更或降级 |
| workspace 选择无效 | 查原生/网页选择器、对话框与完整路径；用已核实的受支持界面 |
| 默认/指定目录不存在或不可访问 | 说明路径及访问证据并询问，不静默回退、不重置默认配置；只打开页面不受缺少默认值影响 |
| 恢复会话与新指定目录冲突 | 保留原会话和进度，先澄清；当前默认值不能覆盖会话项目 |
| 项目测试/构建失败 | diff、独立复现、输入/依赖；交 dsh 定点修复，不重启服务 |
| EPERM/沙箱/DNS/许可证 | 明确命令与受限资源，正常审批或获准替代；不绕过限制、不代签协议 |

网页断线期间后台可能仍在执行。重启前确认进程归属、会话、后台写入及恢复能力。用户原有服务有其他任务时不自行重启，先恢复连接或说明具体影响。不要清空配置、覆盖修改、关闭安全限制来排错。

## Token 相关异常

先限定到同一次失败请求：会话/请求标识、时间、阶段（开发步骤或压缩摘要）、真实模型与提供方、结构化错误 code、HTTP 状态、finish reason、必要的短错误正文及 Retry-After。只读必要日志片段并脱敏；不打印完整配置、认证头或整份聊天日志。旧错误、不同请求和网页连接错误不能拼成一次故障。用户口述“token 用完”、回复突然结束、HTTP 429 单独出现都不足以证明余额不足。

| 分类 | 足够支持的证据示例 | 处理 |
|---|---|---|
| 上下文达到上限 | 当前 dsh `CONTEXT_WINDOW_EXCEEDED`，或当前提供方明确指出输入/请求超过 context window | 核验并优先使用现有压缩；原会话确实无法继续才交接到同项目的新会话 |
| 单次输出达到上限 | 当前回复的 `finish_reason: length`，已核对版本的 dsh 归一化为 `max-tokens` | 检查回复、工具调用和实际文件是否完整，从确定断点继续剩余部分 |
| 接口限流 | 当前 dsh `RATE_LIMIT`，或已核实提供方的请求速率错误及等待信息 | 有界退避；已有内部重试时只跟进，不叠加提交 |
| 账户额度/余额不足 | 当前 dsh `QUOTA`、提供方明确的额度耗尽错误；官方 DeepSeek 的 HTTP 402 | 停止无效重试、保存进度，说明需补充额度或用户决定可用配置 |
| 不足/冲突 | 只有“token”、不完整日志、来源不明的 429，或同次证据矛盾 | 明确“尚不能判断”，补取最小证据，不盲目压缩、切模型或循环重试 |

结构化错误优先，但仍核对请求归属和实际提供方。代理/兼容接口不一定遵循 DeepSeek 状态码，不能因模型名包含 DeepSeek 就假定其 HTTP 含义。某些提供方用 429 表示额度耗尽，应结合错误 code/body；不要把它机械当限流。请求大小错误 413、认证错误 401、输出预算与输入共同超过窗口也要按实际语义区分。详情及当前支持边界见 [兼容性核对](compatibility.md#token-恢复能力核对)。

### 上下文上限与换会话

1. 先检查主 Agent、子 Agent、workflow/Teams、后台 jobs 与内部压缩/重试是否仍在运行，核对提交状态、实际文件和 diff。现有任务正在恢复时观察该任务；提交是否接受不明时查同会话，不另起副本。
2. 核对当前版本、preset、已启用插件和网页可用命令。已存在自动压缩/重试就观察结果；确认空闲且支持时通过网页发送一次 `/compact`（已核对版本无参数），核对接受、压缩结果与当前会话状态。安装了相关包不等于当前会话启用；不能调用内部 JS/RPC 代替支持的界面。
3. 压缩本身可能调用模型并消耗预算。明确压缩成功后在原会话继续剩余工作；“没有可压缩历史”、busy、未产生有效摘要、保存失败、取消、部分变更均不是成功。busy 先等现有执行结束；状态变化/保存失败先复查日志与当前历史，不机械重试。若摘要请求也发生限流、余额不足或输出截断，按其实际错误重新分类，不反复压缩。
4. 压缩不能保证缩小系统提示、工具定义、单个不可拆分的巨大消息；按已核实功能缩小下一次携带的日志/附件或拆分输入，不删用户文件、不削弱需求、不擅改模型或全局 token 参数。功能不可用或有依据的压缩仍无法恢复时，判定原会话不可继续并保存下方交接记录；旧会话无法再回答时，由 Codex 根据已有记录、实际文件和验证补齐，标明缺失信息，不能为了取摘要反复发付费请求。
5. **先确认所有旧写入者停写，再迁移。** 正在后台运行则等待，或通过已支持的停止方式结束当前重复/失控执行并验证停止；“主回复结束”不等于后台停写。无法确认时保存阻塞，不让两个会话写同一批文件。
6. 重查原项目路径、分支/HEAD、diff、未跟踪文件和当前运行状态。分支/文件已变化时重新判断已完成项，不能按旧摘要回滚或重复修改。在同一原项目创建一个后继会话，默认目录不覆盖它；选择完整 workspace 路径后，重新检查模型、完全权限及原任务指定的推理等级（未指定则 High）。只提交精简交接和剩余任务；记录新 session id 和接受状态。重试恢复时优先找这个后继会话，不再创建副本。

### 单次输出上限

先确认截断的是面向用户的文字、压缩摘要还是模型工具调用。读取实际文件、工具执行结果和 diff，按原验收标准检查；不能从结尾有无“完成”判断代码是否写完，也不能执行或补发半截工具调用。

若只缺说明，明确要求“从上一回复的某节/最后完整项继续，只补剩余说明”；若实现未完成，给出文件位置、已验证部分、剩余验收项与禁止重复的操作，拆成较小步骤继续。回复不完整但代码可能已经完成时先验收，避免重做整个任务。摘要截断不代表可以采用半份摘要开新会话，须补齐/核对交接；不自动增大输出上限或换模型。

### 接口限流

以服务端有效的 Retry-After（秒数或 HTTP 日期）/明确重置时间为最早重试边界；保留收到错误的时间。无有效等待信息才用有界退避，例如 5、10、20 秒逐步增加到 60 秒。**单次等待最多 60 秒不等于把服务端总等待截成 60 秒**：分段等待，总等待超过剩余预算则记录阻塞，不能提前重试。

先查 dsh 是否已在等待或重试同一步；内部重试符合服务端等待及任务预算时只观察，不重复发送用户任务。内部策略若会提前重试或服务端等待已经超过剩余预算，通过受支持方式停止本任务的重试并确认状态；不能仅停止外层提交而让内部继续消耗。实际计数应合并 dsh 内部请求、Codex 触发的重试、压缩和切换会话的消耗；不能每次换会话就重置任务预算。重试计数或状态看不清时先取证，不假定为零。结束内部重试后，只有状态已确认、预算允许，才通过当前受支持的失败步骤重试/同会话继续入口恢复一次；没有精确重试入口时从已验证断点明确继续，不能重放原任务。每次等待后重查提交、后台任务和错误是否已变化。

达到下方预算/无进展边界时，停止新增请求；若内部无限重试仍在进行，用受支持的停止控件取消本任务并确认静止，再保存记录。不要以网页刷新、重启服务或无限重试替代恢复。没有实际已安排且获授权的后续执行机制，不承诺“限额恢复后自动继续”；记录待用户继续时重查的时间与条件即可。

### 账户额度或余额不足

立即停止无效请求和压缩，不用新会话绕过额度。若 dsh 内部仍重试，停止该任务并确认后台状态；无受支持停止入口时明确报告仍可能运行和需要用户停止的对象，不声称已停。保存当前进度，说明需要用户补充额度，或决定另一种已经可用的配置；不充值、不购买、不用其他账户、不更换密钥。

只有用户已授权的备用模型/服务商才可切换，且先核对工具与代码能力、上下文容量、指定推理等级及数据使用范围是否覆盖当前私有代码/资料；范围不匹配则询问，不先传数据。通过现有支持的配置控件选择，核对实际提供方和生效状态。新路由继续原目标和验收，不能把切换成功作为完成。没有已验证额度查询能力就报告余额未知，不虚构 dsh 查询命令；Codex 自身额度工具不能证明 dsh 提供方余额。

## 重试、时间和费用边界

用户预算优先。无具体预算的小修复可从单 Agent、约 10–15 分钟、至多 2 次有依据的修正开始；复杂任务按里程碑估计。数字是起点，不要求无进展也重试满额。

同一操作两次同错且无新证据时暂停该操作，换证据来源或报告阻塞；明确额度耗尽、凭据或审批阻塞立即停止对应请求。限流没有用户指定预算时，同一故障的额外重试合计至多 2 次，包含已观察到的 dsh 内部重试；内部策略允许更多次不构成增加任务预算的授权。不要循环刷新、重复提交或不断安装。预算内且持续进展可继续；达到硬上限先保留进度，超限由用户决定。用户明确设定的合理重试/时间/费用限制优先，不通过重置会话绕过。

真实费用不可读时明确未知，用轮次/并发/时间约束，不能声称精确费用已受控。若用户给出硬性金额上限，先确认提供方有可验证的强制额度限制，或能基于已核实计费和请求上界证明不会超限；不能做到时暂停新增付费调用并请用户选择可执行的约束，不能以时间/轮次代理替代金额承诺。单次等待不超过 60 秒并合理退避；持续工作给有效进度，也可做不依赖阻塞的部分。

## 交接与轻量记录

只打开不建记录文件；短任务在 Codex 对话保存摘要。长任务/中断必要时才在项目外获准的私有位置写单个权限 0600 的记录。临时目录重启可能消失，长期恢复应选持久私有目录，不往公共仓库塞状态文件。

字段按需：项目路径、分支/HEAD、已有修改摘要、dsh 版本/profile、PID/进程归属、无 query/fragment/userinfo 的服务 origin、workspace 路径/标识、session id、任务标识、目标/范围/验收、目标推理等级及是否来自用户明确指定、最近核验的会话权限与等级、阶段、最近已确认消息、提交是否接受、文件所有权/子任务状态、预算余额、阻塞、下一步。恢复后重新核验设置，记录中的旧值不能当作当前状态。

**因上下文上限迁移时必须交接：** 用户目标与约束、原项目绝对路径、分支/HEAD（无 Git 明记）、原有和本轮修改、已完成/未完成事项、关键决策及必要依据、原验收项及实际验证结果、当前错误/请求阶段、下一步、旧会话及后继会话标识、仍在运行的任务与停写证据、预算和未确认之处。摘要以一页左右为宜，必要代码只给路径/位置，不复制全聊天、全日志或全 diff。保存权限 0600，放在项目外的获准私有目录；只将经复核且必要的摘要提交给后继会话。

必要记录同时保留已确认的项目及来源；恢复时先核对原会话目录，当前默认项目不参与覆盖。目录不可访问或与本次明确指定冲突时按 [项目规则](projects.md) 处理，不机械重放。

不保存 token、Cookie、API key、完整认证 URL、凭据文件或含秘密的原始日志。恢复先核对服务、页面会话、分支和 diff；PID 会复用、标题会变、token 会轮换。记录用于核对，不机械重放启动、提交或安装。

恢复成功仅表示可以继续执行。按 [任务与验收](task-loop.md) 核对真实产物，原验收项全部满足后才完成；模型切换、压缩和会话迁移都不能降低要求。

## 只读恢复检查脚本

遇到上述故障可用 `python3 scripts/recovery_check.py < /absolute/private/observation.json` 复核下一步。输入只放脱敏结构化观察，不放原始日志；脚本不连接 dsh、不重试、不创建会话、不修改文件，不读取密钥。退出 0 表示观察已解析，**不代表获准执行或任务完成**；输出始终 `executes_actions: false`、`task_complete: false`，无效输入退出 2。读取网页和实际文件仍由 Codex 完成，不能填入猜测值。

输入 JSON 的字段按需要提供：

- `error`：当前请求 `code`（已核实的 dsh code）、`provider`（实际官方 DeepSeek 才写 `deepseek`）、`http_status` 或 `finish_reason`（`length`/`max-tokens`）。仅有 429 时，必须另外核实正文是限流才能给 `rate_limit_confirmed: true`。脚本故意不按自由文本关键词猜测；未知错误由 Codex 查当前提供方资料，不改写成臆测的 code。
- `budget`：`remaining_seconds`、`calls_allowed`（已有授权且符合预算）、`retries_used`（合计已核实次数）、`retry_limit`（未指定则 2）、`no_progress_errors`（同操作连续无进展次数）。压缩费用和内部重试也由调用者累计；脚本不查询余额或计费。使用前补全实际计数，不把缺失数字当作已知零。
- `state`：`run` 为 `idle/stopped/running/retrying/compacting/unknown`；`writers` 为 `quiescent/active/unknown`；`submission` 为 `accepted/not_accepted/completed/unknown`。`files_checked/diff_checked/jobs_checked` 必须来自本次重查。迁移另填 `target_project/branch/head`，与交接基线比较。
- `rate`：原 `retry_after`、`received_at`（收到该错误的 Unix 秒）；`now` 可省略取当前时间。数值等待需要接收时间，HTTP 日期直接算剩余等待；输出 `delay_seconds` 为总等待，`wait_chunk_seconds` 为单次上限。等待结束仍需重查状态，不能机械循环调用或发送。
- `recovery`：`compaction` 为 `unknown/available/unavailable/succeeded/failed/no_history`；available 须证实当前支持且空闲。迁移还需 `old_session_unusable/handoff_saved/handoff_reviewed`；输出续写需 `breakpoint_verified`。布尔值只反映已完成检查。
- `handoff`：`goal/constraints/project/branch/head/changes/done/remaining/decisions/validation/error/next_step/acceptance/old_session/uncertainties`；已创建后继会话则加 `successor_session`。无 Git 用明确 `n/a`，无未知项可填空列表，其余信息不全要补齐，不能编造。脚本只校验关键项存在及迁移路径/基线，不是密钥扫描器；脱敏和内容完整性必须人工复核。

`observe_existing` 不提交；`reconcile_submission` 先查接受状态；`stop_retry_and_record` 包含通过受支持方式停掉失控内部重试并保存进度；`save_handoff/review_handoff` 完成后重新查现场；`create_successor_same_project` 仅建议创建，不允许跳过网页 workspace/权限/推理检查；`restore_successor` 必须查已有后继会话，不能再次创建。所有恢复动作仍遵守前述实际取证与预算规则。
