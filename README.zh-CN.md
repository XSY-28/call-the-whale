# 呼叫蓝色大肥鱼 🐋

[English](README.md) | **简体中文**

**通过 Codex 调度 DeepSeek Harness，完成开发、审查与迭代。**

这是一个面向 Codex 桌面应用的 skill：你给出项目与任务，Codex 整理要求，通过右侧内置浏览器交给 [DeepSeek Harness（dsh）](https://github.com/deepseek-ai/deepseek-harness)执行，再检查实际文件和行为。不满足验收标准时，反馈具体问题并跟进修正。

大肥鱼负责开工，Codex 负责验收。

**呼叫蓝色大肥鱼 / Call the Whale** 是项目品牌，**`call-the-whale`** 是 GitHub 仓库名称，**`$dsh-dev`** 是实际调用方式；安装目录与技术标识仍为 `dsh-dev`。

> **本 skill 的开发任务默认使用完全访问权限，用户明确的任务权限配置优先。** dsh 执行任务时可能读写本机文件、运行终端命令并访问网络；实际范围取决于 dsh 的权限配置、运行账户及操作系统限制。请仅在你信任并愿意授权的环境中使用。它不是严格限制在项目目录内的安全沙箱。

安装不等于授权，也不会修改 dsh 全局权限。首次需要启用完全访问时，Codex 先说明影响并核对授权；已有覆盖当前范围的有效授权不重复询问，但工具或网页要求的当次确认仍须遵守。只打开与纯聊天不自动扩大权限，聊天也不代表安全沙箱。每次新会话检查实际权限和推理等级；推理默认 **High**，用户指定其他等级时沿用。完全访问不扩大任务范围，也不能绕过操作系统限制。

这是社区项目，**并非 DeepSeek 或 OpenAI 官方产品**。用户自行承担 dsh 模型接口费用，Codex 的使用限制独立适用；不保证所有任务成功或完全无人值守。

## 开始使用

### 1. 先配置 dsh，确认环境

**使用本 skill 前，请先自行运行并使用至少一次 DeepSeek Harness（dsh），完成 API key 配置，并确认能够正常发送请求、获得模型回复。** 按照 [dsh 官方说明](https://github.com/deepseek-ai/deepseek-harness)完成首次使用。

还需要：

- Codex 桌面应用，以及实际可用的**内置浏览器展示、网页交互、终端执行与项目读取工具**。仅能加载 skills 或打开链接不够。
- 当前 dsh 版本要求的 Node.js 和 npm/npx。
- Python 3.9+，用于标准库辅助脚本；Git 与构建、测试工具按项目需要提供。

本 skill 不申请 API key、不充值、不提取其他应用凭据。认证在 dsh 中完成；**不要将 key 粘贴到 Codex 对话、仓库文件、Issue 或截图中**。界面显示模型名不证明接口可用，缺配置或认证失败时先回到 dsh 处理，再委托任务。

### 2. 安装 skill

在 Codex 中发送：

```text
请使用 $skill-installer，从 https://github.com/XSY-28/call-the-whale/tree/main/skills/dsh-dev 安装此 skill，保留目录名 dsh-dev。
```

[官方安装器](https://github.com/openai/skills/tree/main/skills/.system/skill-installer)通常安装到 `$CODEX_HOME/skills/dsh-dev`，未设置时为 `~/.codex/skills/dsh-dev`。以安装器报告的位置为准，避免重复副本；下一轮对话调用 `$dsh-dev`。安装的是 `skills/dsh-dev` 子目录，不是仓库根目录。

安装曾用官方安装器的 Git 方法验证。Python 下载遇到证书错误时，修复该运行时证书配置或使用 `--method git`，不要关闭 HTTPS 验证。已有同名安装不会被覆盖，按[更新方法](#更新与卸载)处理。

本文描述 `main` 的当前行为。可以用已发布标签替换链接中的 `main` 来固定版本，但 **`v0.1.0` 不包含后续新增的消息、验收和开发模式规则**。

### 3. 打开页面，再提交一个范围明确的任务

先检查浏览器能力，不提交任务：

```text
使用 $dsh-dev，只打开 dsh，不提交开发任务。
```

阅读上面的完全访问说明后，将占位路径换成自己的项目，并写清应该通过的行为：

```text
使用 $dsh-dev，在 /absolute/path/to/project 修复登录表单的重复提交问题。
保留现有接口；验证双击只发送一次请求，失败后仍能重试。
我理解并授权本次任务使用 dsh 完全访问权限。
```

Codex 确认 workspace 和范围 → dsh 实现 → Codex 检查 diff 并验证行为 → 不通过则定点修正。最终报告给出修改文件、逐项通过/失败/未验证状态、证据及具体阻塞。**这是用法示例，不是已运行的登录表单实测。**

## 选择请求

| 在 Codex 中发送 | 行为 |
|---|---|
| `使用 $dsh-dev，只打开 dsh。` | 寻找或启动服务，在内置浏览器展示；不发消息、不提交开发任务。 |
| `使用 $dsh-dev 发送“你好”。` | 原文发送一次，确认接收并取得完整回复；非项目聊天无需默认项目，不附开发要求或插件。 |
| `使用 $dsh-dev，在 /absolute/project 修复……` | 确认项目，整理任务，委托、独立验收并修正。 |
| `使用 $dsh-dev，继续刚才修复登录表单的任务。` | 找原会话，保留其已确认项目和验收标准，先核对实际执行状态。 |

普通开发请求或讨论 dsh 本身不会自动触发委托。问候不会追加到正在开发的会话，使用可识别的空闲聊天或新建会话。文件、代码审查或修改请求仍走项目和验收规则；会话不唯一、新目录与原项目冲突时先澄清。

## 项目与默认目录

临时指定项目，或明确保存默认值：

```text
使用 $dsh-dev，将 /absolute/path/to/project 设为默认项目。
使用 $dsh-dev，修改默认项目为 /absolute/path/to/another-project。
使用 $dsh-dev，清除默认项目。
```

当前明确目录优先，**不会覆盖默认值**。新的项目任务没有路径时读取已保存默认；未设置则先询问，再提交。不擅自采用 Codex 当前目录、dsh 启动目录或网页上次 workspace。目录不可用时说明原因，不静默切换。

指定文件时保留它为任务对象，从项目证据确认根目录，不直接把父目录当项目根。继续任务沿用原会话项目，忽略后来变更的默认值。只打开和非项目消息不要求默认目录。提交项目任务前必须核对 dsh 网页实际选择的完整 workspace 路径。

| 位置 | 内容 |
|---|---|
| Skill 安装目录 | `SKILL.md`、references、脚本；由更新与卸载管理 |
| 目标项目 | 用户项目文件；保护已有工作，按任务范围修改 |
| 本机配置 | `$CODEX_HOME/dsh-dev/config.json`，否则 `~/.codex/dsh-dev/config.json`；只在明确管理默认目录时改变 |
| 进度与交接 | 项目及安装目录外的私有记录，按用户目录或 CODEX_HOME 解析；与配置分离，原子替换并使用平台支持的私有权限 |

个人配置与执行记录不随 skill 发布，更新和卸载保留这些内容。参见[配置格式示例](examples/project-config.example.json)与[项目选择规则](skills/dsh-dev/references/projects.md)。

## 开发与验收

**dsh 默认写代码，Codex 负责调度和独立验收。** 委托前读取项目约束及已有修改，完成后检查实际文件、diff、未跟踪文件，以及相应测试、构建或界面行为。Codex 需要改同批文件时，先确认 dsh 及写入子任务停止，再交接。

多项要求使用稳定验收编号，修正和恢复不丢项。报告可以这样呈现：

| 验收项 | 状态 | 证据 |
|---|---|---|
| 双击只发一次请求 | 通过 | 独立观察的请求记录 |
| 失败后可以重试 | 失败 | 复现步骤与实际错误 |
| 必需的浏览器覆盖 | 未验证 | 缺少相应环境或检查 |

表格为示例。关键项失败或未验证不能宣布整体完成；dsh 自述只是线索，不代替证据。修正指出失败项并保留已通过行为；简单任务几句话即可。

长任务按依赖划分少量里程碑，给出产物、允许范围及检查方式。摘要跟踪实际进展、下一步、写入责任、提交状态与剩余预算；重复状态不算进展。没有新回复或网页断线不证明后台停止，重启前先查执行状态。旧记录与 PID 不构成可靠锁。

### 能力如何选择

- **服务：** 先读终端输出，再按需查进程、监听和标签页；只复用已确认就绪的服务。否则使用当前版本支持的 `npx @deepseek-ai/dsh web --no-open`，取得实际认证网址并在内置浏览器打开，不猜端口、重复启动或额外打开系统浏览器。无项目请求可用系统创建的私有临时启动目录，但不保存为默认。
- **插件：** 有具体收益才搜索，检查实际可用性、兼容性、维护、权限及用法，按需最少安装。候选、已安装、运行可用和任务实测是不同状态；找不到插件本身不阻塞任务。
- **GitHub 调研：** 成熟功能、陌生集成或复杂设计可能受益时，比较少量相关项目的真实链接、兼容性、维护和许可证，区分借鉴思路、引入依赖与复制代码。stars 不代表质量，依据足够后进入实现，不擅自换栈。
- **执行：** 按依赖、沟通需求、成本及实际能力选择单 Agent、普通子 Agent、workflow、Agent Teams，以及是否独立审评。明确角色与文件职责；Teams 不自动隔离文件，不假装启用了不可用模式。

详见[能力选择](skills/dsh-dev/references/capabilities.md)与[提交及验收](skills/dsh-dev/references/task-loop.md)。

### MVP 与敏捷迭代

要求 **MVP（Minimum Viable Product，最小可行产品）** 时，先做最小可运行核心流程，延后非核心功能。占位按钮或假结果不能替代已要求的行为；代码验收不等于市场需求已验证。

要求**敏捷迭代**时，每轮执行 **dsh 实现与自审 → Codex 独立核验 → 用户审查**。收到本轮反馈后才进入下一轮，沉默或上轮批准不算本轮通过。普通任务与里程碑不会自动增加该审查关卡。

```text
使用 $dsh-dev，在 /absolute/project 做课程报名 MVP。
核心是保存报名，重启后仍能查询；支付和美化延后。

使用 $dsh-dev，在 /absolute/project 用敏捷方式开发。
每轮先由 dsh 自审，再独立核验并交我审查，收到我的反馈后才进入下一轮。
```

每个开发任务默认要求可维护代码：遵循已有结构，集中可变规则和配置，分离实际变化边界，避免为未知未来过度抽象。MVP 与敏捷可组合，它们是委托规则，**不是额外的 dsh CLI 模式或插件**。参见[开发模式](skills/dsh-dev/references/development-modes.md)。

### Token 异常与恢复

按实际证据分类，不能只凭“token 用完”判断：

| 类型 | 处理 |
|---|---|
| 上下文达到上限 | 优先已核实的压缩；原会话无法继续才保存精简交接，在原项目创建一个后继会话。 |
| 单次输出达到上限 | 查回复、工具结果和文件，从明确断点只续剩余部分。 |
| 接口限流 | 按服务端等待信息有界退避，计入已观察的内部重试，不重复提交。 |
| 账户额度或余额不足 | 停止无效重试并保存进度，由用户补额度或授权合适备用配置；不充值、不换密钥或账户。 |
| 证据不足或冲突 | 说明未知，补取最少脱敏证据。 |

交接保留目标、约束、项目/分支、修改、决策、完成与未完成项、验证、错误和下一步，不复制全聊天或凭据。恢复前重查文件、diff、提交状态与后台写入；恢复不代表完成，也不降低验收要求。

用户预算优先，压缩、重试和多 Agent 都可能增加费用。费用不可读时明确未知，不声称精确受控；换会话不重置预算。没有真实后续执行机制时，不承诺当前 Codex 任务结束后自动继续。详见[恢复规则](skills/dsh-dev/references/recovery.md)。

## 更新与卸载

先结束正在执行的 dsh 开发和 skill 维护。首次取得独立源码克隆时运行：

```sh
git clone https://github.com/XSY-28/call-the-whale.git
cd call-the-whale
python3 tools/manage_skill.py update
```

已有克隆时，先检查本地改动，在该目录运行 `git pull --ff-only`，再执行同一更新命令。[维护脚本](tools/manage_skill.py)只管理技能文件，不联网、不启动 dsh、不改配置或权限。

默认目标为 `$CODEX_HOME/skills/dsh-dev`，否则 `~/.codex/skills/dsh-dev`；其他安装位置用 `--skills-dir '/absolute/path/to/skills'`。旧 skill 备份到 `$CODEX_HOME/backups/dsh-dev`（默认 `~/.codex/backups/dsh-dev`），未知个人文件原地保留，替换失败恢复旧件。已知文件的本地改动留在备份中，不自动合并，更新前先核查。

在同一源码目录卸载：

```sh
python3 tools/manage_skill.py uninstall
```

两种操作均报告实际目标与备份，下一轮对话核对是否生效。不会删除默认配置、交接、dsh 会话/profile 或已有权限。撤回权限在 dsh 中操作；恢复旧版先停相关任务，再让 Codex 用报告的备份替换同一安装，并保留个人设置。

## 遇到阻塞时

- **找不到 skill：** 检查 `dsh-dev` 内是否直接有 SKILL.md，确认实际安装位置；重复副本先核查再处理。
- **缺配置或认证失败：** 自行完成 dsh 配置并获得一次回复，不向 Codex 或 Issue 提供 key。
- **项目或浏览器不可用：** 应明确缺少的目录/工具或会话冲突，不静默换目标。
- **断线或限流：** 继续同一任务，先核对原有执行；反复发送可能造成重复工作。
- **权限疑问：** 已核对的完全访问预设映射到 `danger-full-access` 和 `never` 审批策略，仍受系统与账户限制。参见[官方权限说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/interaction/permission-presets/README.md)。

反馈请提供系统与 Codex/dsh 版本、缺少的工具、最小复现、预期/实际行为、脱敏错误 code 和已做检查。私人路径替换为占位值，不附密钥、认证网址、cookies、全聊天、私人代码或未脱敏截图。敏感问题按 [SECURITY.md](SECURITY.md)处理。
